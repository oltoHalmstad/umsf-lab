# BLE protocol (implementation notes)

The authoritative byte-level specification is shared by projects P1, P2 and P3. It is copied unchanged
in [`PROTOCOL_v1.0.md`](PROTOCOL_v1.0.md) (SHA-256
`afd129e011798740d37fd2dceaf0eefad3617552448a4b5292f1523b55e919ff`). This page records how
`umsf-ble-firmware` 1.0.0 implements it and where the spec left a choice.

## GATT

| Characteristic | UUID suffix | NimBLE properties used | Notes |
|---|---|---|---|
| TELEMETRY | `…0002…` | NOTIFY | PHYSIO_FEATURE / STATION_STATE frames, always with 4-byte fragment header |
| EVENT | `…0003…` | NOTIFY, INDICATE | the gateway subscribes for notifications; delivery is guaranteed by the application ACK, not by indications |
| ACK | `…0004…` | WRITE, WRITE_ENC, WRITE_AUTHEN | ACK frame, source_class 3 |
| STATUS | `…0005…` | READ(+ENC, AUTHEN), NOTIFY | bare STATUS frame (no fragment header), every 30 s |
| CONFIG | `…0006…` | WRITE, WRITE_ENC, WRITE_AUTHEN | CONFIG frame; persisted in NVS; changes logged as `CFG,…` |
| COMPACT | `…0007…` | NOTIFY | stationary node only; 20-byte packet every 200 ms, no fragment header |

On top of the characteristic permissions, the node never notifies before the link is encrypted with
MITM protection. It also drops ACK/CONFIG writes that arrive over an unencrypted link or that are not a
CRC-valid frame with `source_class = 3`.

Requested MTU is 247 (ATT payload 244). A 50/52-byte frame then fits one notification
(`frag_count = 1`). At the default MTU 23, frames are split into 16-byte chunks (4 fragments).

## Field encoding choices

| Item | Choice in this implementation |
|---|---|
| `device_id` | up to 4 ASCII bytes, NUL-padded; compared over 4 bytes |
| `boot_id` | NVS counter, starts at 1, skips 0 and 0xFFFF |
| `sequence` | per boot, from 1, **shared by telemetry and events** (cumulative ACK); STATUS reuses the last value |
| `msg_id` (fragment header) | u16 counter per node link, wraps |
| EVENT `value` | i32 ×1000 in the unit of the event table (`impact_excursion`: g ×1000 = mg) |
| EVENT `related_seq_lo` | low 16 bits of the latest telemetry sequence when the event was raised |
| STATUS `sensor_flags` (personnel) | uses the `channel_flags` bit layout (T, PPG, Motion, –, GSR) for detected sensors |
| COMPACT `flags` | same bits as STATION_STATE.flags, from the current 1 s window |
| Synthetic HR | `700 + (seq mod 11) × 10` (70.0–80.0 bpm), only with `synthetic_hr_enabled`, always flagged HR_SYNTHETIC |
| SpO2 | always null (0xFFFF); SPO2_VALIDATED never set |

## Text log line

`umsf_text_line()` produces the spec section 3 formats. The flag letters are T, P, M, H, G, S, in that
order. With `channel_flags = T|P|M` the paper record is reproduced exactly:

```
RX,AG1,152639,F,A01,1,13,122488,2219,1187,97,76,TPM
```

If the HR_SYNTHETIC bit is also set (as in the `physio_paper_stage1_A01` test vector), the spec adds
the letter `H`: `...,76,TPMH`. `hr_x1` is `hr/10` rounded half up. Station `flags_hex` is two uppercase
hex digits.

## JSON (MQTT)

`frame_hex` (lowercase) is always included, so P1 can verify the CRC and decode independently.
Additional choices:

- Physio: `quality` = `quality_pct/100` (2 decimals); `motion_rms_g` = mg/1000; `ppg_ir` = raw mean
  counts; `hr_synthetic` mirrors bit 3. `zone_id` and `worker_pseudonym` are emitted only when the gateway
  has them. The gateway does not have the roster, so pseudonyms are normally P1's job.
- Station: `pir_presence` is null when the PIR is not marked OK in `sensor_flags`. `attachment_verified`
  is true only if the gateway enrollment table says the mounting was verified at commissioning **and**
  the frame does not carry `attachment_uncertain`.
- Event: `level` is a string (`info`, `notice`, `warning`, `urgent`). `value` is the decoded number
  (`value/1000`). `unit` comes from the event table. `quality` is null. `ack_state` is `unacknowledged`.
  `event_id` = `<site>:<originator device>:<boot>:<seq>`. `provenance` = `{source: "<source_class>:<originator>",
  method: …}`. Extension keys: `gateway_id`, `boot_id`, `sequence`, `frame_hex`.
- Node STATUS is published to `…/status` with `"kind":"node_status"`. The gateway's own status uses
  `"kind":"gateway_status"`.

## Test vectors

`test_vectors.json` (project root) is generated by `tools/gen_vectors` from the codec. It is checked
independently by `tools/verify_vectors.py`, a Python decoder written from the spec tables. Each entry:
`{name, note, length, hex, expected:{header:{…}, payload:{…}, crc_ok}}`. COMPACT entries have a flat
`expected` dict. Measurement fields that hold their null sentinel are JSON `null`. Flags, counters and
identifiers are raw integers. One deliberately corrupted frame (`physio_crc_corrupted`) has
`crc_ok: false`. `examples/mqtt_samples.jsonl` shows the JSON records for some of the vectors.
